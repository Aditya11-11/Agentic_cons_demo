## 1. Company and Product Overview

PayGate Pro is a fictional payment gateway platform for SaaS companies. It helps businesses accept payments, manage subscriptions, configure webhooks, and monitor billing events.

PayGate Pro supports two environments:
- Test environment: Used for development and testing. Test API keys start with `pg_test_`.
- Production environment: Used for live payments. Production API keys start with `pg_live_`.

Customers should never use production API keys in public frontend code.

## 2. Support Channels and SLA

Support is available through:
- Email support: support@paygatepro.example
- Dashboard support ticket
- Priority support for Enterprise customers

Standard SLA:
- Free plan: response within 72 business hours
- Starter plan: response within 48 business hours
- Growth plan: response within 24 business hours
- Enterprise plan: response within 4 hours

Urgent issues include payment outage, duplicate charges, security incidents, and production webhook failures affecting more than 100 transactions.

---

## 3. Refund Policy

PayGate Pro offers refunds under the following conditions:

1. Monthly subscription refund:
   Customers can request a refund within 14 calendar days of the initial monthly subscription payment.

2. Annual subscription refund:
   Customers can request a refund within 30 calendar days of the initial annual subscription payment.

3. Duplicate charge refund:
   If a customer was charged twice for the same invoice or subscription cycle, PayGate Pro will refund the duplicate charge after verification.

4. Non-refundable cases:
   - Usage-based overage charges are not refundable once consumed.
   - Refunds are not available for accounts terminated for policy violations.
   - Refunds are not available after the allowed refund window.

Refund processing time:
- Approved refunds are usually processed within 5 to 10 business days.
- Some banks may take additional time to reflect the refund.

Required information for refund requests:
- Account email
- Invoice ID
- Payment date
- Last four digits of the card
- Reason for refund

## 4. Duplicate Charge Handling

If a customer reports being charged twice, the support assistant should collect:

- Customer account email
- Invoice ID or transaction ID
- Date of charge
- Charged amount
- Last four digits of the payment card
- Screenshot or bank statement reference, if available

The ticket should be categorized as:
- Category: Billing
- Priority: High
- Sentiment: Frustrated or Neutral depending on customer tone

The support team should verify whether:
- Two successful payment records exist for the same invoice
- One payment is only an authorization hold
- The second charge belongs to a different subscription or workspace

If it is confirmed as a duplicate charge, the duplicate payment should be refunded.

## 5. Failed Payment Troubleshooting

Common reasons for failed payment:
- Insufficient funds
- Bank declined the transaction
- Incorrect card details
- Expired card
- 3D Secure authentication failure
- Billing address mismatch
- Card not enabled for international payments

Recommended steps:
1. Ask the customer to verify card details.
2. Ask the customer to check with their bank.
3. Ask the customer to try a different card.
4. Ask the customer to update billing address.
5. If 3D Secure fails repeatedly, escalate to the billing operations team.

A failed payment does not always mean the customer was charged. Some banks show temporary authorization holds. These usually disappear within 3 to 7 business days.

## 6. Subscription Cancellation

Customers can cancel a subscription from:
Dashboard > Billing > Current Plan > Cancel Subscription

Cancellation rules:
- Cancellation takes effect at the end of the current billing cycle.
- The customer can continue using paid features until the billing cycle ends.
- Deleting a workspace does not automatically cancel the subscription.
- Enterprise cancellations require a written request from the account owner.

Information to collect before cancellation:
- Account email
- Workspace name
- Reason for cancellation
- Whether the customer wants immediate access removal or end-of-cycle cancellation

## 7. API Key Management

API keys are used to authenticate requests to the PayGate Pro API.

API key best practices:
- Use test keys for development and production keys only for live payments.
- Never expose secret API keys in frontend code.
- Rotate keys every 90 days.
- Revoke unused keys immediately.
- Use separate keys for different services or environments.

API key states:
- Active: Can be used for API requests.
- Revoked: Cannot be used and should return an authentication error.
- Expired: Cannot be used after the expiry date.

If a customer suspects an API key leak:
1. Revoke the suspected key immediately.
2. Generate a new key.
3. Update backend services with the new key.
4. Review recent API usage logs.
5. Contact security support if suspicious activity is detected.

## 8. Webhook Configuration

Webhooks allow customers to receive event notifications from PayGate Pro.

Supported webhook events:
- payment.success
- payment.failed
- payment.refunded
- subscription.created
- subscription.cancelled
- invoice.created
- invoice.paid
- api_key.revoked
- security.alert

Webhook endpoint requirements:
- Must use HTTPS in production.
- Must respond with a 2xx status code to mark delivery as successful.
- Should respond within 10 seconds.
- Should verify the webhook signature.
- Should be idempotent because the same webhook may be delivered more than once.

Webhook signing:
- Every webhook request includes `X-PayGate-Signature`.
- Every webhook request includes `X-PayGate-Timestamp`.
- The receiver should reject requests where the timestamp is older than 5 minutes.
- The signature is generated using HMAC-SHA256 over the timestamp and request body.

Webhook retry policy:
- If the endpoint does not return a 2xx response, PayGate Pro retries delivery.
- Retry attempts happen after approximately 30 seconds, 2 minutes, 5 minutes, 15 minutes, and 30 minutes.
- After 5 failed attempts, the delivery is marked as failed.
- Failed deliveries can be manually replayed from the dashboard.

---

## 9. Webhook Delivery Logs

The webhook delivery log shows:
- Event type
- Webhook URL
- Delivery status
- HTTP response code
- Attempt count
- Response time
- Last error message
- Timestamp of last attempt

Delivery statuses:
- Pending: Delivery has not started.
- Success: Endpoint returned a 2xx response.
- Retrying: Delivery failed and will be retried.
- Failed: Delivery failed after all retry attempts.
- Cancelled: Delivery was cancelled by an admin or system rule.

If a customer says they did not receive a webhook:
1. Check whether the webhook URL is active.
2. Check the delivery logs.
3. Verify the endpoint returned a 2xx response.
4. Confirm the endpoint was reachable.
5. Ask the customer to check their server logs.
6. If needed, manually replay the delivery.

## 10. Account Access and Password Reset

If a customer cannot log in:
- Ask them to verify the email address.
- Ask them to use the password reset option.
- Ask them to check spam/junk folder for the reset email.
- Confirm whether SSO is enabled for their workspace.

Password reset link:
- Expires after 30 minutes.
- Can be requested again after 60 seconds.
- Should not be shared with anyone.

If the account owner is locked out, escalate to Account Recovery.

## 11. Priority and Sentiment Classification Guide

Suggested priority:
- Urgent: Production outage, security incident, duplicate charge affecting multiple customers, webhook outage affecting more than 100 transactions.
- High: Duplicate charge, failed production payments, account owner locked out, production webhook failures.
- Medium: Refund request, single failed payment, API key rotation help, subscription cancellation.
- Low: General product question, documentation request, test environment issue.

Suggested category:
- Billing: Refunds, duplicate charges, invoices, subscription cancellation, failed payments.
- Technical: API errors, webhooks, authentication, integration setup.
- Account: Login, password reset, account owner changes, workspace access.
- Security: API key leak, suspicious activity, unauthorized access.
- General: Product FAQs and non-urgent questions.

Suggested sentiment:
- Angry: Customer uses strong negative language or threatens escalation.
- Frustrated: Customer is upset but cooperative.
- Neutral: Customer asks for help without strong emotion.
- Positive: Customer is satisfied or appreciative.

---

## 12. Escalation Rules

Escalate to Billing Operations when:
- Duplicate charge is confirmed or likely
- Refund amount is above $500
- Annual subscription refund is requested
- Payment dispute or chargeback is mentioned

Escalate to Security when:
- API key leak is suspected
- Unauthorized access is reported
- Suspicious usage spike appears
- Customer mentions compromised account

Escalate to Engineering when:
- Production webhook delivery is failing for many customers
- API latency is above 2 seconds for more than 15 minutes
- Multiple customers report payment processing errors
- A customer provides reproducible API failure logs

Escalate to Account Recovery when:
- Account owner is locked out
- Customer lost access to SSO provider
- Workspace ownership transfer is requested

## 14. Answers the Assistant Should NOT Invent

The assistant should not invent:
- Real refund approval status
- Actual payment confirmation
- Customer account ownership
- Internal employee names
- Personal phone numbers
- Bank-specific refund timelines beyond general estimates
- Production incident status not present in the knowledge base

If the answer is not available in the knowledge base, the assistant should say:
"I do not have enough information in the uploaded support documents to answer that accurately."

## 15. Sample Customer Issues

1. "I was charged twice for my subscription yesterday."
Expected behavior: classify as Billing, High priority, ask for invoice ID, charge date, amount, and last four card digits.

2. "My webhook endpoint is not receiving payment.success events."
Expected behavior: classify as Technical, ask for webhook URL, event type, delivery ID, and error logs.

3. "I think my API key was leaked."
Expected behavior: classify as Security, Urgent priority, recommend revoking the key and generating a new one.

4. "How long does a monthly subscription refund window last?"
Expected behavior: answer 14 calendar days.

5. "How many webhook retry attempts happen after failure?"
Expected behavior: answer 5 attempts after approximately 30 seconds, 2 minutes, 5 minutes, 15 minutes, and 30 minutes.

6. "Can I cancel my subscription immediately?"
Expected behavior: explain cancellation usually takes effect at end of billing cycle; collect account email and workspace name.

7. "What is the CEO's personal phone number?"
Expected behavior: say there is not enough information in the uploaded support documents.
